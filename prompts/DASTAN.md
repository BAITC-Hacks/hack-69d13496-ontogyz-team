# Задание Codex Дастана — интерфейс и демо

Обновление: после общего каркаса отдельно подготовлен локальный интерфейс `web/`. Если он уже перенесён в `main`, сначала проверь браузерный сценарий, доступность элементов и работу ошибок, затем исправь только выявленные проблемы в своей зоне. Не создавай параллельный интерфейс.

Ты помогаешь Дастану в команде Ontogyz на HackAlem AI. Участники не видят чужие чаты. Официальный приватный репозиторий `BAITC-Hacks/hack-69d13496-ontogyz-team` уже клонирован на Windows; базовая ветка `main`, собственная ветка `dastan/ui`. Приступай после сообщения Али об общем коммите: `git status --short --branch`, `git remote -v`, `git fetch origin`; если дерево чистое, `git switch main`, `git pull --ff-only origin main`, запиши точный базовый SHA через `git rev-parse HEAD`, затем `git switch -c dastan/ui`. Если ветка есть, не перезаписывай работу; проверь состояние. Прочитай `AGENTS.md`, `docs/PLAN.md`, `docs/CONTRACTS.md`, `docs/EVAL.md`, README. Если общей основы ещё нет, сообщи Али. Не меняй файлы Али/Тимура.

Твоя зона: только `web/`, `docs/status-dastan.md`, и свои проверки интерфейса в `web/`. Стек: обычные HTML/CSS/JavaScript без сборки, Python/FastAPI у Али отдаёт сайт и API с одного адреса `http://127.0.0.1:8000`; запросы `fetch('/api/...')`. Не добавляй новую зависимость/конфигурацию без Али. Пользовательский текст вставляй через `textContent`/создание DOM, не через `innerHTML`. Для демо покажи переключатель «Бизнес / Команда» с явной пометкой демо-режима; это не настоящая авторизация.

Сделай три области: (1) бизнес вводит краткое описание, получает минимум 3 вопроса, вводит ответы, видит AI-черновик всех десяти полей и может редактировать/подтверждать их; видит рейтинг, девять частей шкалы, список отсутствующих данных, рост баллов и публикует карточку; (2) все студенческие команды видят опубликованный каталог, фильтруют `topic`/`level`, сортировка серверная, задачи с рейтингом ниже 40 тоже доступны, можно самостоятельно подать отклик с идеей, планом, сроком и URL; (3) бизнес видит любые отклики своей демо-задачи, выбирает или отклоняет каждый независимо, в том числе несколько выбранных; при подтверждении этапа видны разовые баллы команды. Адаптация мобильного не обязательна, но интерфейс должен быть понятным для демонстрации за 5 минут. Показывай загрузку, ошибки API и успех каждого действия; не подменяй результат фиктивными данными в готовом сценарии.

Точный контракт: `docs/CONTRACTS.md`. Базовый запрос `{ "draft":"В магазине много списаний. Хотим их сократить.", "topic":"Ритейл" }` → `POST /api/ai/questions` → `{questions:[{id,field,text},...]}`. `POST /api/ai/card` принимает `{draft,topic,answers:[{question_id,answer}]}` → `{card,topic}`. У `card` строки `title,context,need,users,data,constraints,expected_result,success_criteria,contact,interaction_format`; `confirmed_fields` — выбранные бизнесом девять ключей рейтинга, не `title`. `POST /api/tasks`, `PUT /api/tasks/{id}`, `POST /api/tasks/{id}/publish`; `GET /api/tasks?topic=...&level=...`; `GET /api/teams`; `POST /api/tasks/{id}/proposals` с `{team_id,idea,plan,duration_days,prototype_url}`; `GET /api/tasks/{id}/proposals`; `PATCH /api/proposals/{id}` с `{status:"selected"}` или `rejected`; `POST /api/proposals/{id}/milestones/confirm`. Ошибка `{error:{code,message}}`, сообщение показывать человеку. AI может отвечать до 45 секунд — состояние загрузки и отмена ожидания после 50 секунд. Не помещай ключ API в JS.

Пример минимальной карточки: `{title:"Сократить списания",context:"В магазине остаются продукты",need:"Снизить списания",users:"Менеджеры",data:"",constraints:"",expected_result:"",success_criteria:"",contact:"",interaction_format:""}`; при подтверждении `context,need,users` результат 30, уровень `draft`, но публикация и отклик доступны. Полную схему, интервалы и ограничения проверь в документе; не меняй названия полей.

Проверь основной сценарий вручную в браузере на работающем сервере; пока сервер Али не готов, можешь проверить только структуру UI, честно сообщи о непроверенной интеграции. Проверь пустые поля, неверный URL, загрузку/ошибку и разные баллы. Подготовь в `docs/status-dastan.md` сценарий демо ≤5 минут с реальными кликами от слабого описания до ручного выбора, результаты проверок и блокировки. Не добавляй новые функции после указанного Али времени заморозки.

Перед сохранением: `git status --short`, проверки, `git add web docs/status-dastan.md`, `git diff --cached`, понятный `git commit -m "Build business and team UI"`, `git push -u origin dastan/ui`. Передай Али ветку, SHA (`git rev-parse HEAD`), какие API проверены на работающем сервере, блокировки и ожидаемое время демо. Не сливай в `main`, не применяй force push/reset hard.
