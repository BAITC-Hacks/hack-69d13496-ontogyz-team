# Задание Codex Али — сервер и интеграция

Обновление: после общего каркаса отдельно подготовлен полный локальный MVP. Сначала проверь, какие из перечисленных ниже функций уже есть в актуальном `main`. Если код перенесён, не переписывай его с нуля: проверь, исправь только ошибки и задокументируй реальные проверки. Старые указания «реализуй» применяй только к отсутствующей части.

Мы команда Ontogyz на пятичасовом HackAlem AI. Ты работаешь в уже клонированном приватном репозитории `BAITC-Hacks/hack-69d13496-ontogyz-team` на Windows. Основная ветка `main`; твоя ветка `ali/server`. Сначала проверь текущую папку, `git status --short --branch`, `git remote -v`, `git log -1 --oneline`, отсутствие конфликтов; прочитай существующие `AGENTS.md`, `README.md`, `docs/PLAN.md`, `docs/CONTRACTS.md`, `docs/EVAL.md`. Если общей основы там ещё нет, попроси Али добавить содержимое предоставленного архива и зафиксировать общий коммит в `main`; не инициируй новый проект вместо официального. Зафиксируй базовый SHA командой `git rev-parse main` и покажи его в отчёте. Не трогай изменения других участников. Не применяй force push или hard reset.

Цель: сквозной продукт из кейса AI Sana. Бизнес даёт короткий черновик, AI задаёт минимум 3 уместных вопроса, составляет редактируемую карточку без выдумки; после подтверждения сервер считает 0–100, публикует карточку; все команды видят каталог и отправляют отклик; бизнес независимо выбирает несколько команд, одну или ни одной; подтверждённый этап разово добавляет баллы. Роли: ты только сервер, SQLite, общий код, Git и README; Тимур отдельно меняет `app/ai/`, Дастан — `web/`. Никогда не редактируй их файлы. Чужие изменения интегрируй после их отчётов, по одной ветке.

Стек: Python 3.12.14 у Али, Python 3.14.3 у Тимура, Python 3.13.1 у Дастана; FastAPI + SQLite + HTML/CSS/JS на `http://127.0.0.1:8000`. Команды PowerShell в README. Ответственный за `requirements.txt`, `.gitignore`, `.env.example`, `AGENTS.md`, `README.md`, схемы и контракты — Али. Ключ только в локальном `.env`, не в Git/чат/браузере/логе; `OPENAI_MODEL` первоначально `gpt-4.1-mini-2025-04-14`, считать доступ непроверенным до отчёта Тимура.

Твоя задача: спроектируй и реализуй `app/schemas.py`, `app/db.py`, `app/scoring.py`, `app/routes/`, подключи их в `app/main.py`; SQLite без миграционного фреймворка; при первом старте заполни синтетические данные не менее 5 черновиков, 5 карточек, 5 команд, 5 откликов, если набор организаторов отсутствует. Уточни в README, что данные синтетические. Контракт неизменен: `docs/CONTRACTS.md`. Дай прозрачную формулу и фильтры, хранение после перезапуска. Код AI Тимура подключай через `app.ai.service.generate_questions` и `build_card` после его передачи; до этого не выдавай статический ответ за AI. Обрабатывай отсутствие ключа, тайм-аут, плохой ответ. Не ограничивай число откликов. `selected` разрешён нескольким предложениям одной задачи; этап даёт 10 баллов однократно только выбранному предложению.

Ключевые API: `POST /api/ai/questions` принимает `{"draft":"...","topic":"Ритейл"}` и отдаёт 3–5 `{id,field,text}`; `POST /api/ai/card` принимает `draft`, `topic`, `answers:[{question_id,answer}]`, отдаёт полный `card` без выдуманных значений; `POST/PUT /api/tasks`, `POST /api/tasks/{id}/publish`, `GET /api/tasks` с `topic` и `level`, `GET /api/tasks/{id}`, `GET /api/teams`, `GET/POST /api/tasks/{id}/proposals`, `PATCH /api/proposals/{id}`, `POST /api/proposals/{id}/milestones/confirm`. У карточки десять строк: `title`, `context`, `need`, `users`, `data`, `constraints`, `expected_result`, `success_criteria`, `contact`, `interaction_format`. Подтверждённые поля — `confirmed_fields` из девяти полей без названия. Веса по именам: `context` 10, `need` 10, `data` 20, `expected_result` 15, `success_criteria` 15, `constraints` 10, `users` 10, `contact` 5, `interaction_format` 5. Ошибка JSON `{error:{code,message}}`.

Работай небольшими проверяемыми шагами. Сначала проверь `/api/health` и подключение маршрутов; затем создание/обновление/публикацию и рейтинг; затем каталог; отклики и решения; затем seed и интеграцию. Минимальные значимые проверки: счёт 0 и 100, пересчёт после подтверждения, опубликованная задача 0–39 видна и принимает отклик, несколько selected, повторный этап не начисляет повторно, неверный ввод, запуск из чистой копии по README. Персональные данные не использовать. Если у тебя нет доступа к репозиторию/общим файлам, сообщи об этом, не строй неподключённую копию.

Перед сохранением: `git status --short`, необходимые проверки, `git add app/main.py app/schemas.py app/db.py app/scoring.py app/routes data README.md requirements.txt docs/status-ali.md` (только реально существующие и свои изменённые пути), `git diff --cached`, затем понятный `git commit`, `git push -u origin ali/server`. Для интеграции дождись коммитов Тимура и Дастана; `git fetch origin`, при чистой рабочей копии объединяй ветки по одной в `main` с проверкой после каждой, затем `git push origin main`. При ошибке остановись и сообщи причину. Итог: что сделано → файлы → проверки → ветка и SHA → отправлено ли → блокировки → следующий шаг. Объясняй Али команды коротко и по-русски.
