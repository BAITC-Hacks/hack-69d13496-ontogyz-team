## Решение

Команда Ontogyz: Али — сервер, SQLite, Git, интеграция и README; Тимур — AI; Дастан — интерфейс и демо. Один сервер FastAPI на порту 8000, SQLite, обычный HTML/CSS/JS. Одна внешняя AI интеграция через OpenAI. Плановый идентификатор `gpt-4.1-mini-2025-04-14`, фактическая доступность подтверждается реальным запросом. Приложение должно принять слабый черновик, задать не менее 3 вопросов, собрать редактируемую карточку без выдуманных сведений, после ручного подтверждения начислить прозрачный рейтинг, опубликовать даже низкорейтинговую задачу, принять неограниченные отклики и дать бизнесу выбрать одну, несколько или ни одной команды.

Официальные требования кейса — из документа «Единый кейс по геймификации практических заданий»; наши технические решения ниже не являются правилами организаторов. Обязательные поля, вес рейтинга, границы уровней и объёмы данных — в `docs/CONTRACTS.md`. Если организаторы не выдали данные: не менее 5 черновиков, 5 карточек, 5 команд, 5 предложений. ## Критический путь

Общий коммит на `main` → собственные ветки в собственных копиях → первый AI запрос и UI к health/API → серверная формула рейтинга → сохранение и каталог → предложения и ручное решение → объединение по одной ветке с проверкой → чистый запуск и демо. Push персональной ветки ещё не означает попадание кода в оцениваемую `main`.

При недоступном API допускается явно названная локальная заглушка с демонстрацией промпта, входа/выхода и некорректного ответа; нельзя выдавать её за внешний AI. Содержательная AI функция и честная демонстрация остаются приоритетом.
