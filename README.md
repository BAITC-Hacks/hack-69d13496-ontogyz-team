# AI Sana Challenge Hub — Ontogyz

MVP для превращения короткой бизнес-задачи в подтверждённую карточку с прозрачным рейтингом готовности. Команды видят общий каталог, откликаются, а бизнес вручную решает, с кем работать.

## Что работает

Бизнес вводит описание, получает вопросы AI, редактирует карточку, отмечает подтверждённые сведения, видит рейтинг и публикует задачу. Студенты смотрят каталог и направляют предложения. Бизнес самостоятельно выбирает или отклоняет несколько откликов и подтверждает этап с однократным начислением 10 баллов. Запуск AI зависит от действительного ключа и доступа к модели; без них интерфейс показывает явную ошибку. Приложение сохраняет записи в SQLite между запусками.

## Запуск в Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

Открыть http://127.0.0.1:8000 и http://127.0.0.1:8000/api/health. Для AI создать `.env` по `.env.example` и поместить ключ только туда. Если `py` отсутствует, заменить на `python`. Подтвердить работу модели отдельным реальным запросом; кандидат `gpt-4.1-mini-2025-04-14`, фактический доступ в аккаунте не подтверждён. Переменная `DATABASE_PATH` необязательна, база по умолчанию в `data/hackalem.db` и не добавляется в Git.

Для проверки API: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`.

Проверки AI-модуля без внешних запросов: `.\.venv\Scripts\python.exe -m unittest app.ai.test_service -v`. Эти тесты используют подмену клиента и не подтверждают доступ к модели или качество реальных ответов. Если ни `py`, ни `python` не доступны в PATH, создайте `.venv` через полный путь к установленному Python: `& 'C:\путь\к\python.exe' -m venv .venv`.

## Архитектура

Один процесс FastAPI отдаёт HTML/CSS/JavaScript и JSON API. SQLite хранит задачи, команды, отклики и подтверждённые этапы. Сервер рассчитывает рейтинг из подтверждённых полей; AI задаёт вопросы и помогает составить редактируемую карточку. Схемы и примеры: `docs/CONTRACTS.md`.

Формула: контекст 10, потребность 10, данные 20, результат 15, критерии успеха 15, ограничения 10, пользователи 10, контакт 5, взаимодействие 5. Только заполненные и подтверждённые поля. Уровни: 0–39 черновик, 40–69 рабочая, 70–89 готовая, 90–100 приоритетная. Каталог сортируется по убыванию рейтинга, затем по id. Задачи 0–39 видны и доступны для отклика. Контент полей и URL проверяются при приёме сервером. Статический демо-переключатель ролей не представляет собой настоящую авторизацию.

## Тестовый сценарий

1. Запустить приложение и проверить `/api/health`. При первом запуске автоматически создаются 5 синтетических черновиков, 5 карточек, 5 профилей команд и 5 предложений. Их источник — команда Ontogyz, они служат только демонстрации.
2. Бизнес вводит «В магазине много списаний продуктов. Хотим сократить их», тему «Ритейл». Получает ≥3 вопроса от API, отвечает на вопросы, редактирует карточку и отмечает только подтверждённые поля.
3. Сохраняет карточку, видит разбивку баллов, дополняет сведения и видит рост рейтинга. Публикует задачу; задача с низким рейтингом тоже видна.
4. В каталоге переключает тему и уровень, открывает задачу. Выбирает команду и отправляет идею, план, срок и действительный URL.
5. Бизнес переходит к откликам, выбирает или отклоняет предложения по одному; может выбрать несколько. Подтверждает этап выбранной команды, баллы начисляются один раз.

## Демо до 5 минут и ограничения

Демо: шаги 2–5 по одной подготовленной задаче, с показом роста рейтинга, низкорейтинговой карточки и ручного решения. Состояние AI и проверенные примеры заносятся в `docs/status-timur.md`, остальные подтверждения — в `docs/EVAL.md`. AI может ошибаться, поэтому бизнес редактирует и подтверждает текст. Контакт и сведения задач в демонстрационных данных вымышлены. Полноценной регистрации, управления правами, защиты бизнеса от чужого редактирования и производственного развёртывания нет.

Внешние материалы: библиотеки FastAPI, Uvicorn, OpenAI Python SDK и их зависимости устанавливаются из `requirements.txt`. Реальные данные организаторов не применялись. Вклад команды: Али — сервер, хранение, рейтинг и интеграция; Тимур — AI, промпты и оценка; Дастан — веб-интерфейс и демо. Этот локальный собранный вариант подготовлен совместно с Codex; фактические персональные вклады уточнить перед сдачей.
