# Общие правила команды Ontogyz

Прочитай `docs/PLAN.md` и `docs/CONTRACTS.md` до правок. Один рабочий репозиторий; каждый участник работает в собственной локальной копии и ветке. Основная ветка `main`; фактическое состояние Git проверяй перед командами.

Али владеет `app/main.py`, `app/schemas.py`, `app/db.py`, `app/scoring.py`, `app/routes/`, `data/`, `docs/PLAN.md`, `docs/CONTRACTS.md`, `docs/EVAL.md`, `docs/status-ali.md`, `README.md`, `AGENTS.md`, `.gitignore`, `.env.example`, `requirements.txt` и общими настройками. Тимур владеет только `app/ai/` и `docs/status-timur.md`. Дастан владеет только `web/` и `docs/status-dastan.md`. Тесты — внутри своей области или после согласования с Али.

Не меняй чужие файлы, не форматируй проект целиком. Зависимости и общий контракт меняет Али после согласования. Ключи — только в `.env` сервера; в Git, чат, клиент и логи не помещать. Не выдавай заглушки за работающий AI.

Работа: проверь `git status --short --branch`, `git remote -v`; сделай правки в своей ветке; проверь функциональность; `git add` с явными путями; `git diff --cached`; коммит; push своей ветки; передай Али ветку, хеш коммита, проверку и блокировки. Не применяй `push --force`, `reset --hard` и удаление чужих файлов. При конфликте остановись и обсуди с владельцем.

Цель: сквозной сценарий из кейса — слабый черновик, минимум три уточняющих вопроса, редактирование и подтверждение, рейтинг 0–100, публикация даже с низким рейтингом, каталог, отклик и ручное решение бизнеса. AI не изобретает факты и не выбирает команды. Подробная схема в `docs/CONTRACTS.md`; при расхождении сначала исправь контракт с Али, затем код.
